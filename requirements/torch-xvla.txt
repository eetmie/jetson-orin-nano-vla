# Backend: stock PyTorch for X-VLA (LeRobot XVLAPolicy).
#
# SEPARATE from requirements/torch.txt on purpose. The X-VLA export tooling only works
# against the layout lerobot 0.6.1 ships, while the SmolVLA side stays on the version
# its checkpoint was exported with. Two lerobot versions cannot share one venv, so
# X-VLA gets its own. Check the module layout rather than the version string — an
# install reporting 0.5.1 here carries an xvla policy with a vendored Florence2.
#
#   pip install -r requirements/torch-xvla.txt
#   pip install --force-reinstall --no-deps torch torchvision \
#       --extra-index-url https://pypi.jetson-ai-lab.io/sbsa/cu130
#   pip install --ignore-installed "numpy>=2.2.6" "scipy>=1.14"     # NOT optional
#
# scripts/13_env_torch_xvla.sh does this in the right order.
#
# The last line is not optional with --system-site-packages: the JetPack `scipy` is
# built against numpy 1.x, shadows through into the venv, and makes `import lerobot`
# fail on "cannot import name 'Inf' from 'numpy'". pip then "resolves" it by
# downgrading numpy, which breaks lerobot's own numpy>=2 pin. Installing both INTO the
# venv settles it.

lerobot[xvla]==0.6.1
-r bench.txt

# Not a mistake: the X-VLA *PyTorch* backend imports preprocess_image from the vendored
# xvla_split_ort, which imports onnxruntime at module scope. Without this the torch
# backend cannot even be imported. The alternative is patching the vendored runtime,
# which would break the guarantee that the measured code is byte-identical to what the
# deploy project runs.
onnxruntime
